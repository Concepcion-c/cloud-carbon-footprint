# 07 — Data Dictionary

> **Summary:** Every data field used in the TRACE app — what it means, what values it takes, where it comes from, and whether it is mock, calculated, or sourced from a real standard. Useful for answering questions about specific numbers or data shapes.

---

## Data status labels

- **Synthetic** — generated by `docs/sample-data/generate.py`; no real data
- **Hand-authored** — written manually for the demo; not generated
- **Calculated** — derived by `app.py` from other fields
- **Sourced** — value comes from a published external source (not generated)
- **Simulated** — appears real in the demo but is static or scripted

## File: `recommendations.json`

**What it is:** Hand-authored optimisation recommendations with expected before/after values. Used to populate the Optimize page cards and drive the live recalculation.

**File path:** `docs/sample-data/recommendations.json`

**Structure per recommendation:**
| Field | Description | Example |
|---|---|---|
| `id` | Unique recommendation identifier | rec-support-bot-rightsizing |
| `title` | Display title | Right-size Support-Bot summarisation + shift region |
| `app` | Target application | Support-Bot |
| `rationale` | Human-readable explanation | "Support-Bot is ~76% of AI carbon..." |
| `actions` | Array of actions to apply | See below |
| `quality_note` | Explicit quality trade-off statement | "30% of traffic kept on large model..." |
| `expected` | Pre-computed expected impact values (for verification) | See below |

**Action object fields:**
| Field | Description | Example |
|---|---|---|
| `type` | Action type: `model_swap` or `region_shift` | model_swap |
| `fraction` | Fraction of app traffic to apply the action to (0–1) | 0.7 |
| `from` | Current model class or region | large |
| `to` | Target model class or region | small |

**Expected values fields (for verification/testing):**
| Field | Description |
|---|---|
| `app_carbon_kg_before` | Expected baseline carbon for the app |
| `app_carbon_kg_after` | Expected carbon after applying the recommendation |
| `app_carbon_pct` | Percentage change in app carbon |
| `total_ai_carbon_*` | Total AI carbon before/after/pct |

**Note:** The `expected` values are used for development testing to verify the live calculation produces correct results. They are not displayed to the user.

## Calculated fields in `app.py`

These fields do not exist in any source file — they are computed by the calculator functions:

| Field | Formula | Produced by |
|---|---|---|
| `ai_energy_kwh` | `(total_tokens / 1M) × kwh_per_1m_tokens` | `calc_ai()` |
| `ai_carbon_kg` | `ai_energy_kwh × g_co2e_per_kwh / 1000` | `calc_ai()` |
| `ai_cost_usd` | `(total_tokens / 1M) × usd_per_1m_tokens` | `calc_ai()` |
| `ai_water_liters` | `ai_energy_kwh × wue_liters_per_kwh` | `calc_ai()` |
| `cloud_carbon_kg` | `usage_kwh × g_co2e_per_kwh / 1000` | `calc_cloud()` |
| `cloud_water_liters` | `usage_kwh × wue_liters_per_kwh` | `calc_cloud()` |
| `co2e_kg` (per span) | `(tokens / 1M) × kwh_per_1m × carbon_kg_per_kwh` | `load_trace_data()` |
| `water_liters` (per span) | `energy_kwh × REGION_WUE[region]` | `load_trace_data()` |
| `energy_debt_score` | `0.6 × carbon_rank + 0.4 × code_risk_rank` | Energy Debt tab logic |

## The `generate.py` data generator

**File path:** `docs/sample-data/generate.py`

Generates all four CSV files deterministically using `random.seed(42)`. Key parameters:

| App | Monthly tokens | Model | Region |
|---|---|---|---|
| Support-Bot | ~800M | large | ap-south |
| Search-RAG | ~400M | small | us-west |
| Doc-Summarizer | ~300M | mid | eu-west |
| Code-Assistant | ~250M | mid | us-east |
| Analytics-Agent | ~120M | large | us-east |

Daily values are created by dividing monthly totals by 30 and applying a ±20% random jitter to simulate realistic day-to-day variation.

**To regenerate:** `cd docs/sample-data && python3 generate.py`

The JSON files (`recommendations.json`, `llm_trace_export.json`, `code_scan_findings.json`, `aiworks_usage_export.json`) are hand-authored and must be updated manually.

---

## Key takeaways

- All data in the TRACE demo is synthetic — no real client, company, or usage data
- The model coefficient values (kWh/1M tokens) are sourced from published hardware benchmarks, not made up
- The grid intensity values are sourced from Electricity Maps, EPA eGRID, and ENTSO-E — the same sources CCF uses
- The WUE values are estimates (Medium confidence); most are from climate and industry survey data
- Calculated fields (carbon, energy, water) are derived at runtime by `app.py`; they are not stored in any file
- The recommendation JSON contains hand-authored `expected` values for internal verification — these are not shown to the user
